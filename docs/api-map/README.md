# เอกสารแผนที่ เมนู → API → ตาราง

ตอบคำถามว่า **หน้าไหนยิง API ตัวไหน ใช้ตารางอะไร อยู่บนเครื่องไหน** และย้อนกลับได้ว่า
**ตารางนี้ถ้าแก้แล้วจะกระทบหน้าไหนบ้าง**

## วิธีสร้างใหม่

```
node docs/api-map/gen-api-map.js
```

ได้ `docs/api-map/tsdc-api-map.html` เปิดด้วยเบราว์เซอร์ได้เลย ไม่ต้องมี server

สคริปต์ไม่ได้เก็บข้อมูลไว้ในตัวเอง แต่ไล่อ่านซอร์สใหม่ทุกครั้งที่รัน

| ลำดับ | อ่านจาก | ได้อะไร |
|---|---|---|
| 1 | `src/app/app-routing.module.ts` | รายชื่อเมนู (`data.menubar`) + component + version |
| 2 | ไฟล์ component ของแต่ละหน้า | หน้านั้นเรียก `dataService.<เมธอด>` อะไรบ้าง |
| 3 | `src/app/services/data.service.ts` | เมธอดนั้นยิงไป URL ไหน แยกเป็น `/api`, `/api2`, `/api99` |
| 4 | ไฟล์ API ทั้งสามตัว | endpoint นั้นใช้ตารางอะไร มีคำสั่งเขียนไหม วิ่งข้ามเครื่องไหม |

## เพิ่มหน้าใหม่แล้วต้องทำอะไร

**ไม่ต้องแก้สคริปต์** แค่รันใหม่ ขอแค่หน้าใหม่นั้น

- ประกาศ route ไว้ใน `app-routing.module.ts` พร้อม `data: { menubar, version, lastupdate }`
- เรียก API ผ่าน `dataService.<เมธอด>` ตามปกติ (ไม่ได้ยิง `http` ตรงๆ จากใน component)

ถ้าอยากให้หน้าใหม่ไปอยู่ในกลุ่มที่ถูกต้องของ sidebar ให้เติม route นั้นลงใน `GROUP`
ที่หัวไฟล์ `gen-api-map.js` — ไม่เติมก็ได้ จะไปกองรวมที่กลุ่ม "อื่นๆ"

## ข้อควรรู้

- สคริปต์จะเตือนท้ายการรันถ้ามี endpoint ที่แมปไม่ได้ ตอนนี้มี 6 จุดของ `/api99`
  เพราะสำเนา `S.13` บนเครื่อง dev เก่ากว่าตัวที่รันจริง ถ้าอยากได้ครบต้องดึงซอร์สจริงจาก 10.26.1.13 มาก่อน
- ชื่อตารางได้จากการอ่านข้อความ SQL ไม่ได้รันจริง endpoint ที่ประกอบ SQL เป็น string
  จากค่าที่ frontend ส่งมาอาจมีตารางที่มองไม่เห็น
- ยังไม่ได้ไล่เข้าไปใน stored procedure
