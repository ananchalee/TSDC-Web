# TSDC Recording Agent

Agent บันทึกวิดีโอจาก **กล้อง USB/webcam ที่ต่อกับ PC โต๊ะเช็ค** สั่งเริ่ม/หยุดจากหน้าเว็บ
`audit-check-tracking` ผ่าน WebSocket

ตามแบบใน `screen_recording_flow.drawio` — **เฟสนี้ทำเฉพาะ A–E (เก็บไฟล์ในเครื่อง)**
ยังไม่มีส่วนอัพโหลดขึ้น server (Sweep Service)

## Flow

```
Browser (Angular)                 Agent (PC โต๊ะเช็ค)
─────────────────                 ───────────────────
scan container → เริ่มงาน
  sendCommand('start', shipment)  →  spawn ffmpeg 1 ตัว เปิดกล้อง (dshow)
                                     ตัดไฟล์เองทุก 5 นาที ด้วย -f segment
                                  ←  {status:'recording', startedAtLocal}
สแกนสินค้า / ปิดกล่อง                (กล้องอัดอยู่เบื้องหลัง)
พิมพ์เอกสารเสร็จ
  sendCommand('stop', shipment)   →  ส่ง 'q' ให้ ffmpeg ปิดไฟล์ล่าสุดให้สมบูรณ์ + ปล่อยกล้อง
                                  ←  {status:'stopped', files:[...]}
```

## ติดตั้ง

1. ต่อกล้อง USB เข้ากับเครื่อง แล้วเช็คใน Windows ว่า Device Manager มองเห็น
2. ติดตั้ง **ffmpeg** — โหลด essentials build จาก https://www.gyan.dev/ffmpeg/builds/
   แตกไฟล์แล้วเอา path ของ `ffmpeg.exe` ไปใส่ `ffmpegPath` ใน `config.json` (หรือเพิ่มลง PATH)
3. ติดตั้งและหาชื่อกล้อง:

```
cd recording-agent
npm install
npm run devices        ← แสดงชื่อกล้อง/ไมค์ที่ต่ออยู่
```

4. ก็อปชื่อกล้องที่ได้ไปใส่ `videoDevice` ใน `config.json` เช่น

```json
"videoDevice": "HD USB Camera"
```

5. รัน agent (ต้องรันค้างไว้ตลอดเวลาที่ใช้งานโต๊ะเช็ค):

```
npm start
```

## config.json

> ⚠️ **ห้ามใส่คอมเมนต์ `//` ในไฟล์นี้** — JSON ไม่รองรับ ถ้าใส่ไฟล์จะ parse ไม่ผ่าน
> ตอน **เปิด agent** จะ **ถอยไปใช้ค่า default ทั้งหมดแบบเงียบๆ** (`videoDevice` กลายเป็นว่าง กด start แล้วขึ้น error หากล้องไม่เจอ)
> อธิบายค่าต่างๆ ไว้ในตารางข้างล่างนี้แทน

**แก้ไฟล์นี้ระหว่าง agent ทำงานอยู่ได้เลย ไม่ต้อง restart** — ทุกรอบที่ส่องกล้อง (5 วินาที)
agent จะดู mtime/ขนาดไฟล์ ถ้าเปลี่ยนก็โหลดใหม่ทับอ็อบเจกต์เดิม (ดู `reloadConfigInto` ใน
`src/config.js`) มีไว้เพื่อขั้นตอนติดตั้ง: เห็นป้ายส้ม → ก๊อปชื่อกล้องที่ถูกใส่ไป → เซฟ →
ป้ายเขียวเองใน 5 วินาที ขั้นตอน "อย่าลืมรัน restart-agent.bat" คือขั้นที่คนลืมบ่อยที่สุด

- **`port` เป็นข้อยกเว้น** — reload ข้ามให้เสมอ เพราะ WebSocket bind ไปแล้วตั้งแต่ตอนเปิด
  ต้อง restart จริงเท่านั้น
- ไม่ reload ระหว่างกำลังอัด เช็คตอนเดียวกับที่ probe กล้อง ซึ่งข้ามอยู่แล้วตอนอัด
- **JSON พังไม่ทับของเดิม** — เจอบ่อยตอนคนเซฟค้างไว้ครึ่งทาง ถ้าเอาค่า default ไปทับ
  ชื่อกล้องที่ตั้งไว้จะหายทันทีเพราะเซฟผิดครั้งเดียว จึงคงค่าเดิมไว้แล้วเขียนเหตุผลลง log
- **BOM ถูกตัดทิ้งก่อน parse** — `JSON.parse` ไม่รับ BOM แล้วพังทั้งไฟล์ด้วยข้อความที่
  อ่านไม่รู้เรื่อง ไฟล์นี้เป็นไฟล์ที่คนเปิดแก้ด้วยมือ บางโปรแกรมเติม BOM ให้เองโดยไม่บอก

| key | ค่า default | ความหมาย |
|---|---|---|
| `port` | `5050` | port ของ WebSocket (ต้องตรงกับ `AGENT_WS_URL` ใน `video-recording.service.ts`) |
| `deskName` | `""` | ชื่อโต๊ะเช็คที่ใช้ขึ้นต้นชื่อไฟล์ — เว้นว่าง = ใช้ชื่อเครื่อง |
| `outputRoot` | `D:/VideoRecord` | โฟลเดอร์หลักที่เก็บวิดีโอ |
| `segmentSeconds` | `300` | ตัดไฟล์ทุกกี่วินาที |
| `ffmpegPath` | `ffmpeg` | path เต็มของ `ffmpeg.exe` ถ้าไม่ได้อยู่ใน PATH |
| **`videoDevice`** | `""` | **ชื่อกล้องจาก `npm run devices` — ต้องตั้งค่าก่อนใช้งาน** |
| `audioDevice` | `""` | ชื่อไมค์ — เว้นว่าง = ไม่บันทึกเสียง |
| `videoSize` | `1280x720` | ความละเอียด — ต้องเป็นค่าที่กล้องรองรับ (`npm run devices` ดูได้) |
| `framerate` | `15` | เฟรมต่อวินาที — ยิ่งต่ำภาพยิ่งกระตุกแต่ไฟล์เล็กลง **ไม่มีผลกับความเร็วในการเล่น** (agent ใช้ `-use_wallclock_as_timestamps` บังคับให้ความยาววิดีโอตรงกับเวลาจริงเสมอ) |
| `inputFormat` | `""` | ใส่ `mjpeg` ถ้ากล้องรองรับ — **กล้องที่ใช้อยู่จำเป็นต้องใส่** เพราะ `yuyv422` ที่ 720p ทำได้แค่ 10fps |
| `rtbufsize` | `256M` | บัฟเฟอร์กันเฟรมหลุดตอนเครื่องทำงานหนัก |
| `crf` | `28` | คุณภาพ (ยิ่งมากไฟล์ยิ่งเล็ก/ยิ่งเบลอ) |
| `preset` | `veryfast` | ความหนักของ CPU ในการเข้ารหัส |

## ผลลัพธ์

ไฟล์วางใน `outputRoot` ตรงๆ **ไม่แยกโฟลเดอร์ตามชื่อ shipment แล้ว** — ชื่อไฟล์มีทั้งโต๊ะ
ออเดอร์ และเวลาอยู่ในตัว จึงไม่ชนกันอยู่แล้ว และตัวอัปโหลดกับคนที่มาตามหาไฟล์ดูโฟลเดอร์เดียวจบ

```
D:/VideoRecord/
  ├── 660-P52-ICCZ14382-Date(2026-08-15)-Time(15-52-48).mp4        ← อัดได้ไฟล์เดียว
  ├── 661-P52-ICCZ14400-Date(2026-08-15)-Time(16-03-11)-001.mp4    ← อัดยาวจนถูกตัด segment
  └── 662-P52-ICCZ14400-Date(2026-08-15)-Time(16-03-11)-002.mp4
```

- `660` = `FNVideo_id` ของแถวนั้นใน `TSDC_VIDEO_HD` — agent เติมให้ทีหลังตามคำสั่ง `rename`
  จากหน้าเว็บ เพราะ id เพิ่งเกิดตอน insert (ดู `API_VIDEO_HD.md`)
- `P52` = เลขโต๊ะเช็คที่หน้าเว็บส่งมา ถ้าไม่ได้ส่งมาจะใช้ `deskName` ใน config แทน
- เวลาคือ **เวลาที่เริ่มอัดรอบนั้น** ออเดอร์เดิมที่เอามาเช็คซ้ำในวันเดียวกันจึงได้ไฟล์คนละชุด
- `-001` ต่อท้ายมีเฉพาะตอนถูกตัดหลาย segment ถ้าได้ไฟล์เดียวจะถูกตัดออกตอนอัดจบ

## Protocol

**เว็บ → agent**

```json
{ "command": "start" | "stop" | "status", "orderCode": "SHIPMENT123" }
{ "command": "rename", "files": [{ "name": "P52-...mp4", "newName": "660-P52-...mp4" }] }
```

`rename` ใช้เติม `FNVideo_id` ไว้หน้าชื่อไฟล์หลัง API คืน id มาแล้ว — ดู `API_VIDEO_HD.md`
agent รับเฉพาะชื่อไฟล์ล้วนใน `outputRoot` (มี `\` `/` `..` หรือไม่ลงท้าย `.mp4` = ปฏิเสธ)
ไม่เขียนทับไฟล์ที่มีอยู่ และไม่แตะไฟล์ที่ ffmpeg ยังเขียนค้างอยู่
**หน้าเว็บสั่งเฉพาะหลังอัดจบ** เพราะ `scanSegments()` หาไฟล์ด้วย prefix เดิม ถ้าเปลี่ยนชื่อ
ระหว่างยังอัดอยู่ ไฟล์จะหลุดจากการ scan รอบถัดไปทันที

**agent → เว็บ** (broadcast ทุก client และส่งสถานะปัจจุบันให้ทันทีที่ต่อเข้ามา)

```json
{ "status": "idle" }
{ "status": "recording", "orderCode": "...", "startedAtLocal": "...", "folder": "...", "elapsedSeconds": 42 }
{ "status": "stopped",   "orderCode": "...", "folder": "...", "files": ["..."] }
{ "status": "error",     "message": "..." }
{ "status": "camera",    "ready": true, "message": "กล้อง \"...\" พร้อมใช้งาน" }
{ "status": "renamed",   "files": [{ "name": "660-P52-...mp4", "nameOld": "P52-...mp4", "path": "...", "sizeBytes": 0 }] }
```

`elapsedSeconds` คือจำนวนวินาทีที่อัดมาแล้ว ณ ตอนส่ง — หน้าเว็บเอาไปเดินนาฬิกาต่อเอง
ส่งเป็นตัวเลขเพราะ `startedAtLocal` เป็นปี พ.ศ. พาร์สฝั่ง JS ไม่ได้ และค่านี้ยังถูกต้อง
เมื่อหน้าเว็บเพิ่งรีเฟรชกลางคันระหว่างที่ยังอัดอยู่

`camera` เป็นสถานะกล้อง **แยกออกจากสถานะการอัด** — ต่อ WebSocket ติดบอกได้แค่ว่า agent
ทำงานอยู่ ไม่ได้แปลว่าอัดได้ agent จึงเรียก `ffmpeg -list_devices` ทุก 5 วินาที
เทียบชื่อกับ `videoDevice`/`audioDevice` ใน config แล้วส่งผลขึ้นไป (ดู `src/camera.js`)

- ตรวจ **2 ชั้น**: กล้องชื่อนั้นมีอยู่ในเครื่องไหม แล้วกล้องตัวนั้นรองรับ `inputFormat`
  กับ `videoSize` ที่ตั้งไว้หรือเปล่า (`ffmpeg -list_options` ของกล้องตัวนั้น)
  ชั้นที่สองจำเป็นเพราะ "กล้องมีอยู่" ไม่ได้แปลว่า "อัดด้วยค่านี้ได้" — `inputFormat: mjpeg`
  ตั้งไว้ให้กล้อง USB ที่โต๊ะเช็ค แต่กล้องในตัวโน้ตบุ๊คหลายรุ่นมีแต่ `yuyv422` แล้ว ffmpeg
  จะตอบแค่ `Could not set video options` + `I/O error` ตอนกดเช็ค ซึ่งอ่านไม่ออกว่าติดอะไร
  ผลของ `-list_options` ถูก cache ไว้ตามชื่อกล้อง+ค่าที่ตรวจ ไม่ได้ถาม ffmpeg ซ้ำทุกรอบ
- ส่งซ้ำเฉพาะตอนค่าเปลี่ยน ไม่ได้ยิงทุก 5 วินาที และส่งให้ทันทีที่ client ต่อเข้ามา
- **ไม่ probe ระหว่างที่กำลังอัด** — ffmpeg ตัวที่อัดอยู่ยึดกล้องไว้ และการอัดได้อยู่
  ก็เป็นหลักฐานว่ากล้องยังดี
- `ready: null` = ยังตรวจไม่เสร็จรอบแรก หรือ socket หลุด (หน้าเว็บจะไม่เปลี่ยนสีป้าย
  จนกว่าจะรู้ผลจริง — agent รุ่นเก่าที่ยังไม่ส่ง `camera` มาก็ค้างที่ `null` แล้ว
  แสดงเขียวตามพฤติกรรมเดิม)
- `message` ถูกเอาไปโชว์ตอนเอาเมาส์ชี้ป้าย จึงต้องบอกวิธีแก้ในตัว เช่นแนบรายชื่อ
  กล้องที่เสียบอยู่จริงมาด้วยเมื่อหาชื่อที่ตั้งไว้ไม่เจอ

## หมายเหตุ

- agent ผูกกับ `127.0.0.1` เท่านั้น เครื่องอื่นในเน็ตเวิร์กเรียกไม่ได้
- กล้องจะถูกเปิดเฉพาะตอนอัด (ไฟกล้องติดตอน start ดับตอน stop) โปรแกรมอื่นเปิดกล้องค้างไว้
  พร้อมกันไม่ได้ — dshow ให้ใช้ได้ทีละโปรแกรม
  การ probe ทุก 5 วินาทีแค่ **ขอรายชื่ออุปกรณ์** ไม่ได้เปิดสตรีม ไฟกล้องจึงไม่ติด
  และไม่ไปแย่งกล้องจากโปรแกรมอื่น
- ปิดหน้าเว็บ/รีเฟรช **ไม่หยุดการอัด** — หยุดเมื่อได้คำสั่ง `stop` เท่านั้น
  เปิดหน้าเว็บใหม่จะได้สถานะ `recording` กลับมาทันทีที่ต่อ WebSocket
- ปิด agent ด้วย Ctrl+C จะสั่ง ffmpeg ปิดไฟล์ให้เรียบร้อยก่อนจบ
- ยังไม่มีการลบไฟล์เก่าอัตโนมัติ — ต้องดูพื้นที่ดิสก์เอง จนกว่าจะทำ Sweep Service
